# ADR-013 — Kotlin Multiplatform Core (Android + Desktop)

- **Status:** Accepted
- **Date:** 2026-08-19
- **Source:** [plan.md §73, §75.1, Phase 10](../plan.md#73-master-plan--product-vision)

## Context

The master plan commits Penly to Android **and** desktop (Windows/macOS/Linux).
The v0.1 architecture already forbids Compose/Activity/ViewModel imports in
`core:*` modules ([ADR-010](ADR-010.md)), so the document/ink/storage logic is
already platform-neutral Kotlin. The question is whether to carry that promise
forward as an explicit Kotlin Multiplatform structure or to defer it.

Deferring is cheaper now but risks a painful late migration as sync, plugins,
AI, and the knowledge layer accumulate Android-only assumptions.

## Decision

Split every platform-free `core:*` module into KMP source sets
(`commonMain` + `androidMain` + `desktopMain`), starting with the
persistence-critical ones (core-model, core-geometry, core-document, core-ink)
and finishing with the capability modules added by the master plan
(core-search, core-export, core-sync, core-ai, core-plugin, core-crypto).

```text
core/*              commonMain       androidMain        desktopMain
core-model          document model   —                  —
core-ink            stroke logic     InkAdapter (AndroidX Ink)   —
core-storage        interfaces       SQLite/FileStore   SQLite/FileStore
core-renderer       interfaces       Android renderer   Skiko renderer
core-sync           protocol         WebView/network    desktop network
```

The Android app keeps AndroidX Ink behind `InkAdapter` ([ADR-002](ADR-002.md));
the document format is unchanged and platform-neutral. The desktop shell is
Compose Multiplatform (multi-window, tray, global shortcuts, native dialogs).

Migration rule: convert module-by-module, keeping Android green
(`./gradlew check`) at every step.

## Consequences

### Positive

- One codebase for document, ink, sync, plugin, and AI logic on both platforms.
- The open note platform can reach desktop users (the larger note-app market).
- Sync/plugins/AI are written once and used twice.

### Negative

- KMP source-set ceremony and expect/actual boilerplate across all core modules.
- Some libraries (Room, AndroidX Ink) remain Android-only and stay behind
  adapters.
- CI must compile and test three targets instead of one.

### Neutral

- Kotlin 2.2+ (already used) has stable, first-class multiplatform support; no
  compiler upgrade needed.
- iOS is deliberately out of scope for this ADR; the same structure leaves that
  door open (per-principle 10).
