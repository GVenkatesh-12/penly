# ADR-019 — Feature-Parity Matrix

- **Status:** Accepted
- **Date:** 2026-08-19
- **Source:** [plan.md §74](../plan.md#74-feature-matrix)

## Context

The master plan's "no compromise" ambition is expressed against concrete
competitors (GoodNotes, Samsung Notes, OneNote, Obsidian, Notion, Logseq).
Without a written benchmark, feature claims drift and scope fights break out.
The plan needs a single source of truth for what "complete" means and in what
order it arrives.

## Decision

Maintain a **feature-parity matrix** at
[`docs/features/feature-matrix.md`](../../features/feature-matrix.md) as the
authoritative benchmark:

- Organized by tier (handwriting, knowledge, platform, future) and mapped to
  the phase that delivers each row (plan §55/§76).
- Each row records: feature, competitor source, current status
  (planned/in-progress/done), and exit criterion or link to its test.
- Updated in the same commit as the phase work that touches it; a release is
  not "feature-complete" for a tier while unchecked rows remain.

Status legend: `planned` → `in-progress` → `done` (with linked verification).

## Consequences

### Positive

- Scope is decidable: a phase is done when its matrix rows are done.
- Competitor claims are concrete and reviewable (e.g. "handwriting search"
  means the on-device OCR index, not a marketing phrase).
- Prevents silent scope creep in either direction (missing or gold-plated
  features).

### Negative

- The matrix must be actively maintained or it rots into a wishlist.

### Neutral

- It is a living document: new competitor features are added as new rows with
  explicit phase assignments or a "deferred" status.
