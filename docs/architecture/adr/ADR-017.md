# ADR-017 — Desktop Ink via Skiko

- **Status:** Accepted
- **Date:** 2026-08-19
- **Source:** [plan.md §75.1, Phase 10](../plan.md#75-master-plan-architecture-strategy)

## Context

AndroidX Ink ([ADR-002](ADR-002.md)) is an Android-only library. The desktop
port (Phase 10) needs ink rendering and authoring on Windows/macOS/Linux with
mouse and pen-tablet (pressure) input. The document format is already
platform-neutral stroke data, so the decision is limited to the
renderer/authoring backend, not the data model.

Options considered:

- **Port AndroidX Ink's native core:** not a supported integration path;
  AndroidX Ink publishes no desktop artifact.
- **Swing/AWT rendering:** weak on performance and anti-aliasing control for
  high-frequency stroke rendering.
- **Skiko (Kotlin Skia bindings):** the same GPU-accelerated approach as the
  Android `Canvas` pipeline; already a transitive dependency of Compose
  Multiplatform.

## Decision

Use **Skiko (Skia)** as the desktop ink renderer and authoring backend in a new
`platform-desktop` module, behind the same `InkAdapter` boundary that isolates
AndroidX Ink on Android.

```text
core-ink (document stroke logic — shared)
      │
      ├── androidMain: AndroidX Ink (via InkAdapter)
      └── desktopMain: Skiko renderer + input pipeline (mouse/tablet)
```

- Input: mouse/tablet events with pressure, mapped through the same
  `InputRouter` seam as Android pointer input.
- Rendering: Skia-native stroke meshes, GPU-accelerated, matching the Android
  look within format-spec tolerances.
- No persisted-format changes: strokes authored on desktop edit and render
  identically on Android (Phase 10 exit criterion).

## Consequences

### Positive

- Skia-based rendering closely matches the Android pipeline's fidelity.
- Reuses the shared ink logic; only the platform renderer/input differs.
- No new heavyweight dependency (Skiko ships with Compose Multiplatform).

### Negative

- Ink quality (pressure dynamics, low-latency authoring) must be re-validated
  on desktop hardware; the AndroidX Ink quality bar is high.
- Mouse-only authoring is a degraded experience; pen-tablet support is required
  before the desktop release can be called parity.

### Neutral

- The `InkAdapter` boundary keeps `core-ink` free of both engines.
