# ADR-015 — Sync Protocol + E2EE

- **Status:** Accepted
- **Date:** 2026-08-19
- **Source:** [plan.md §73, §75.5, Phase 14](../plan.md#73-master-plan--product-vision)

## Context

Principle 15: "your data, your servers." Users must be able to sync across
devices without giving their notes to a third party. The v0.1 plan already
establishes an operation log ([plan §33](../plan.md#33-operation-log)) for
recovery; that same log is the natural sync seam. Principles 2 and 15 forbid a
mandatory account or cloud-first storage.

## Decision

Build `core-sync` on the **operation log**, with pluggable transports and
client-side end-to-end encryption:

```text
operation log (per document)
      │  transport adapter (WebDAV → S3 → official server)
      ▼
core-sync (diff/apply, clock, conflict policy)
      │
      ▼
core-crypto (XChaCha20-Poly1305, Argon2id-derived keys)
```

- **Transport order:** WebDAV first (universal self-host, zero infra for
  users), S3-compatible second, official hosted service third (optional).
- **E2EE:** client-side XChaCha20-Poly1305 AEAD; keys derived from a user
  passphrase via Argon2id; both blobs and metadata are encrypted; a
  passphrase-protected vault is unreadable server-side.
- **Conflicts:** last-writer-wins with explicit conflict copies and a
  resolution UI first; CRDT for ink strokes arrives with collaboration
  (Phase 17).
- **Background sync:** WorkManager on Android, a desktop service on desktop.
- **Safety bar:** sync ships only after fault-injection tests prove no
  committed content is lost (kill-a-device, reorder, partial-write cases).

## Consequences

### Positive

- Users can self-host from day one of the feature; official cloud is optional
  and never a requirement.
- Reuses the recovery operation log — one mechanism for recovery, history, and
  sync (principle 10's seam pays off).
- E2EE makes the self-hosted path trustworthy without server-side trust.

### Negative

- E2EE is unforgiving of implementation errors; crypto must be reviewed and
  tested, and key loss means data loss (needs a clear backup UX).
- WebDAV implementations vary; transport-level compatibility work is real.
- Offline/online edge cases (reorder, concurrent edits) need careful protocol
  design and test coverage.

### Neutral

- CRDT for strokes can be layered onto the log later without a format change.
