# ADR-018 — Plugin Security / Capability Model

- **Status:** Accepted
- **Date:** 2026-08-19
- **Source:** [plan.md §75.2, Phase 13](../plan.md#75-master-plan-architecture-strategy)

## Context

Plugins ([ADR-014](ADR-014.md)) execute third-party JavaScript inside Penly.
Notes are the user's most private data (privacy model in
[`docs/privacy/privacy-model.md`](../../privacy/privacy-model.md)). Principle
16: "plugin sandboxing is security" — third-party code must never touch notes
without explicit, user-granted capabilities. This is a security architecture,
not a hardening task.

## Decision

Adopt a **capability-based security model** enforced at the bridge boundary:

```text
capabilities (declared in plugin manifest, granted at install):
  notes:read        read notes/pages (no write)
  notes:write       create/edit notes and pages
  commands          register commands/actions
  ui:view           render custom views/panels
  network           make network requests (no file-system access ever)
  ai                invoke AI providers
  tools:agent       register agent tools
```

Enforcement rules:

- The JS host has **no** filesystem or raw network access; all I/O goes
  through capability-checked SDK calls.
- Execution limits: memory ceiling, per-call timeout, cancellation on
  unresponsiveness.
- Bundles are **signed**; signatures and SDK-version compatibility are verified
  at install. Updates re-verify and re-grant (unchanged capabilities carry
  over; new ones require user consent).
- The bridge is JSON-only and fuzz-tested (structure, types, size limits).
- Plugins are disabled during recovery/journal-replay paths and never block
  startup or save.

## Consequences

### Positive

- Users get an understandable grant model ("this plugin can edit notes, no
  network") instead of all-or-nothing trust.
- Worst-case compromise is bounded by the granted capabilities.
- The same model serves the marketplace (curated review + signed bundles).

### Negative

- Capability enforcement must be exhaustive at every SDK entry point; a single
  missed check is a hole. Requires dedicated tests and fuzzing.
- JS-bundle signing needs key management (signing keys, revocation) and a
  registry.

### Neutral

- Plugin authors get a clear contract; capabilities are discoverable via the
  SDK manifest at install time.
