# ADR-004 — Local-First Storage

- **Status:** Accepted
- **Date:** 2026-08-14
- **Source:** [plan.md §1, §4, §11–13](../plan.md#11-database-schema)

## Context

The product promise is "digital paper with the reliability of a database": a note must be created and edited with no account, no network, and no cloud service. Data must be lossless and crash-safe.

## Decision

Adopt a **local-first** architecture:

- All note content, metadata, journal, and recovery data live on-device in app-private storage.
- No mandatory accounts, no network dependency for any core writing flow.
- Database (Room/SQLite) for metadata/indexes/transactional state; file store for large opaque payloads ([plan §12](../plan.md#12-file-store)).
- Crash-safe journaled persistence with autosave ([plan §13](../plan.md#13-crash-safe-write-pipeline)).
- Every document-changing operation is identifiable (operation ID, document ID, revision, timestamp) so sync/backup can be added later without redesign ([plan §33](../plan.md#33-sync-architecture-preparation)).

## Consequences

### Positive

- Users own their data; zero-friction first-run experience (pen within seconds).
- No server costs, no accounts to manage, works offline always.
- Privacy-first by construction; telemetry optional and opt-in ([plan §37](../plan.md#37-telemetry-philosophy)).

### Negative

- Sync/collaboration must be added later through the prepared seams; no cloud backup in v0.1.
- The app alone is responsible for data durability → crash-safety and integrity work is mandatory, not optional.

### Neutral

- Sync (WebDAV/self-hosted) is planned for later versions ([plan §60](../plan.md#60-future-roadmap-compatibility)).
