# ADR-010 — Modular Architecture

- **Status:** Accepted
- **Date:** 2026-08-14
- **Source:** [plan.md §6–7, §68](../plan.md#6-architecture)

## Context

Penly must stay testable without Android UI, remain portable (desktop/iOS via KMP later), and avoid architectural debt while growing into PDF annotation, search, sync, AI, and collaboration. A monolithic app module makes this impossible.

## Decision

Use a **layered, modular, unidirectional architecture** with a multi-module Gradle project from the beginning:

```text
app/          — application shell
core/*        — core-common, core-model, core-document, core-ink, core-geometry,
                core-renderer, core-storage, core-database, core-search,
                core-export, core-pdf, core-settings, core-telemetry
feature/*     — feature-home, feature-notebook, feature-editor, feature-settings
editor/*      — editor-canvas, editor-tools, editor-selection, editor-gestures, editor-history
platform/*    — platform-android, platform-file-picker, platform-share, platform-stylus
testing/*     — testing-fakes, testing-fixtures, testing-benchmarks
```

Dependency direction (one-way, enforced):

```text
feature → editor/core/platform
editor  → core + platform
core    → core only
platform→ Android-specific APIs
app     → feature modules
```

Never allowed: `core-model → Compose`, `core-model → Activity`, `core-model → ViewModel`. No downward layer imports a higher-level feature package.

## Consequences

### Positive

- Core logic is unit-testable on the JVM with no Android UI.
- Compilation boundaries make architectural violations visible at build time.
- Future KMP/desktop ports reuse core modules.

### Negative

- More build configuration and module ceremony up front.
- Requires discipline: dependency direction is enforced by CI checks and review.

### Neutral

- This is the structure that lets the Ink Lab sample live independently (`samples/ink-lab`, [plan §54](../plan.md#54-ink-lab-sample)).
