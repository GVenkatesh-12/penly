# ADR-014 — Sandboxed QuickJS Plugin Runtime

- **Status:** Accepted
- **Date:** 2026-08-19
- **Source:** [plan.md §73, §75.2, Phase 13](../plan.md#73-master-plan--product-vision)

## Context

The master plan makes plugins a first-class product pillar (principle 11:
"extensible by default"). The ecosystem lesson from Obsidian is that a
user-installable plugin market is what turns a good note app into a platform.

Options considered:

- **Native Kotlin plugins (dynamic feature modules):** safe and fast, but no
  community marketplace and hostile to third-party distribution on Android
  (Play dynamic-feature constraints, per-release verification).
- **GraalJS / V8 (J2V8):** full ECMAScript but multi-MB binaries and a large
  sandboxing surface.
- **QuickJS:** small (~1 MB), embeddable, clean C API, fast startup, widely
  used for sandboxed scripting (e.g. in-app automation).

## Decision

Embed **QuickJS** as the plugin runtime in a new `core-plugin` module with a
host wrapper in `platform-plugin-host`. Plugins are JavaScript bundles with a
manifest; they interact with Penly exclusively through the **`penly-sdk`** — a
typed, versioned, async JSON-bridged API.

```text
JS plugin (bundle + manifest)
      │  JSON-RPC-style async bridge (capability-checked)
      ▼
platform-plugin-host (QuickJS, memory/time limits)
      ▼
core-plugin (SDK dispatch, capability enforcement, lifecycle)
      ▼
core-* (document, search, ai, ...)
```

SDK stability is a product promise: `penly-sdk` v1 is locked in Phase 13 with a
compatibility test suite, and SDK versions are negotiated at plugin install
time.

## Consequences

### Positive

- A real community plugin market is technically possible (signed bundles, no
  Play-store dependence for distribution).
- Small footprint fits the "lean dependency" constraint of the repo.
- The capability model (ADR-018) gives users understandable, explicit control.

### Negative

- JavaScript is a second language in a Kotlin codebase; the SDK needs careful
  docs and typings.
- QuickJS is a vendored/native dependency (JNI); builds and updates must be
  handled carefully.
- Sandbox escapes are a real threat model — requires the security work in
  ADR-018 (fuzzing, limits, signed bundles) to be treated as feature work, not
  hardening.

### Neutral

- Plugins run identically on Android and desktop (the bridge is platform-free;
  only the host wrapper is platform-specific).
