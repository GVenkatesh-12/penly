# ADR-002 — AndroidX Ink as Ink Foundation

- **Status:** Accepted
- **Date:** 2026-08-14
- **Source:** [plan.md §4, §9, §48](../plan.md#9-ink-data-model)

## Context

Penly's core value is natural stylus writing. Rolling a complete ink engine (geometry, brushes, rendering, storage, serialization) in-house is expensive and error-prone; depending on an unstable library is unacceptable for a v0.1 whose persisted format must survive for years.

## Decision

Use **AndroidX Ink 1.0.0 (stable)** for the v0.1 production path.

- AndroidX Ink 1.0.0 became stable on 2025-12-17; the 1.1.0 line is still alpha and must not become a hard dependency of the v0.1 persisted format or core document model.
- AndroidX Ink provides authoring, rendering, brush, geometry, strokes, and storage modules, including low-latency in-progress stroke rendering.
- Prefer AndroidX Ink's stroke representation and serialization at the storage boundary instead of inventing a second incompatible representation without a strong reason.
- **However**, the own document format must not directly depend on an unstable Ink internal wire representation. An `InkAdapter` isolates `DocumentInk` from AndroidX Ink.

## Consequences

### Positive

- Proven, stable, low-latency ink rendering without a from-scratch engine.
- Upstream maintenance and evolution of brush/geometry/storage APIs.
- Future 1.1+ features remain adoptable through the adapter.

### Negative

- Dependency on a specific library's APIs; must follow the adapter discipline strictly.
- Partial/pixel eraser availability depends on the library's persistence path (see [plan §20](../plan.md#20-eraser-strategy)).

### Neutral

- Version upgrades must run migration and recovery tests ([plan §5 rule 10](../plan.md#5-dependency-policy)).
- Ink Lab (`samples/ink-lab`) validates the integration before full-app work ([plan §54](../plan.md#54-ink-lab-sample)).
